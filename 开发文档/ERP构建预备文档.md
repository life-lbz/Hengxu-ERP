# ERP 构建预备文档

## 1. 工程命名

| 用途 | 名称 |
| --- | --- |
| 中文工程名 | **衡序 ERP** |
| 英文工程名 | **Hengxu ERP** |
| 建议仓库名 | `hengxu-erp` |

「衡」对应库存、成本和账务的核对。「序」对应采购、销售、生产与结算的业务流转。名称覆盖商贸和制造，也便于后续新增业务模块。本文将它作为内部工程名。

## 2. 产品定位与行业判断

衡序 ERP 服务于有库存与财务协同需求的中小企业。系统覆盖采购、销售、仓储、应收应付、总账和基础生产管理，使采购人员、业务员、仓管、生产人员和会计围绕同一套单据工作。

**商贸分销与制造可以放在同一套产品里。建议用商贸分销验证通用底座，用按单或小批量装配验证制造模块。** 两类企业共用物料、采购、销售、仓库、库存流水和财务。生产在这套底座上增加一条物料转换链，由工单将原材料转为在制品或产成品。销售既可交付外购商品，也可交付自产成品，仓库和财务沿用同一套接口。

| 目标企业 | 重点需求 | 建议覆盖范围 |
| --- | --- | --- |
| 商贸分销企业 | 采购与销售、多仓调拨、库存周转、往来对账 | 启用进销存与财务，生产按公司启用 |
| 装配型制造企业 | BOM、工单、缺料检查、领退料、完工入库、生产成本 | 在通用底座上启用制造，支持分批完工和按工单归集成本 |
| 工序密集或流程制造企业 | 有限产能排程、配方与联副产品、车间实时采集 | 作为后续细分行业扩展，立项前按客户样本验证 |

建议选一家**同时做外购转售和简单装配**的企业作为样板。同一客户订单可以同时包含外购件和自产件，适合检验两类业务能否共享物料编码、库存及利润口径。

## 3. 业务模块和单据闭环

| 模块 | 核心业务与单据 |
| --- | --- |
| 组织与档案 | 公司、部门、用户角色、客户、供应商、物料、计量单位、仓库、价格、科目、成本中心 |
| 采购 | 采购订单、收货、退货、供应商发票、应付、付款与核销。支持订单、收货、发票三单匹配 |
| 销售 | 销售订单、库存预留、发货、退货、销售发票、应收、收款与核销。支持部分交付和部分回款 |
| 仓储 | 入库、出库、调拨、盘点、库存预留、库存流水和估值。库存查询区分现存量、预留量和可用量 |
| 制造 | BOM 版本、生产工单、领退料、报废、完工入库、工单结算和成本差异分析 |
| 财务 | 会计期间、凭证、总账、应收应付明细、银行对账、试算平衡、资产负债表和利润表 |
| 经营分析 | 查询订单履约、库存价值、账龄、销售毛利、工单成本和差异。报表可下钻到单据 |

**业务按单据行关联。** 采购订单一行可分批收货，供应商一张发票可覆盖多次收货，付款也可跨多张应付单核销。系统要记录关联的数量或金额，才能算清待交付、未开票和未结余额。销售、退货和生产领料同样保留来源行及对应数量。

**制造成本以工单为归集对象。** 工单下达时锁定 BOM 版本和标准用量，记录实际领料、退料、报废、人工和制造费用。人工和制造费用先允许财务按工单录入或分配。完工可分批入库，未完工部分留在在制品。工单结算核对材料与费用归集、完工转出及在制余额。若分批完工采用暂估成本，结算差额应通过可追溯的成本调整处理，并考虑该批成品已出库的情况。

**财务根据业务动作生成凭证。** 以永续盘存的样板账套为例，采购收货触发库存与暂估，供应商发票用于处理暂估和应付，销售发货结转库存成本，销售发票确认应收和收入，收付款更新往来核销，生产领料转在制，完工转成品。具体科目、触发时点、税额和采购价差的处理须由目标企业财务确认，并固化到过账规则。报销、固定资产、预算和薪酬可按业务需要接入同一套凭证与权限体系。

## 4. 自研核心和工程约束

**推荐采用模块化单体。** 技术栈初选 FastAPI、PostgreSQL、React + TypeScript，沿用当前项目熟悉的技术。采购、销售、库存、制造、财务各有自己的应用接口。确认一次发货时，发货状态、库存流水和对应会计分录通过同一个数据库事务提交。外部通知、报表计算和 AI 任务可以异步执行。

- **核心自研。** 自己掌握单据状态、数量与金额分配、库存估值、BOM 和工单、会计分录生成、冲销与核销。数据库、认证、文件存储和表格组件可复用成熟工具。ERPNext 和 Odoo 用于参考业务模型和边界场景。[ERPNext](https://github.com/frappe/erpnext) · [Odoo](https://github.com/odoo/odoo)
- **单据状态按业务定义。** 区分草稿、待审、已确认、已过账和已冲销等状态。明确每种单据在哪个动作生效，有下游单据时按依赖顺序更正。冲销保留原单编号、原因与操作人。
- **库存以流水为依据。** 流水记录公司、仓库、物料、数量、单位成本、来源单据行和时间。余额由流水汇总。并发出库和重复请求由事务与数据库唯一约束控制，默认禁止负库存。
- **账务满足记账约束。** 过账时校验借贷平衡、会计期间、科目和往来对象。金额、数量、汇率和单位成本使用定点数，明确各自精度和舍入时点。按来源业务动作建立唯一过账记录，防止重试产生重复凭证。
- **权限覆盖业务范围。** 用户权限按公司、部门或仓库限定，区分制单、审批、出纳和记账。审计记录包含操作人、对象、时间、变更与原因。
- **样板账套先收敛口径。** 默认用单法人、人民币、多仓库和一种库存计价方法验证。初选按公司与物料计算移动加权平均成本，库存数量按仓库管理。数据保留公司维度。多币种、跨公司交易和合并报表等需求在有真实业务样本后确定。正式上线使用的计价方法、期间和科目由财务确认。

## 5. AI 扩展与 AuditFlow 的位置

ERP 管理单据、库存和账簿。AI 服务通过受控接口，按用户权限读取数据、生成建议或提交待人工确认的草稿。建议记录关联的原始数据、规则或模型版本、处理结论和采纳人，便于追溯。过账、付款和库存调整由 ERP 的权限、审批与规则控制。

| 应用方向 | 可落地的功能 |
| --- | --- |
| 文档录入与审核 | 从订单、发票和报销附件提取字段，生成草稿并标注原文位置。AuditFlow 可从费用审核切入，返回审核结果与证据 |
| 业务异常处理 | 由确定性规则发现采购三单差异、重复发票、欠料与成本偏差，由 AI 汇总上下文并解释原因，提交给对应负责人 |
| 经营问答 | 查询客户欠款、商品毛利和工单超支原因。答案附统计口径与单据链接，沿用用户的数据访问权限 |
| 计划辅助 | 利用销量、交期、现存量和预留量提出补货或生产建议，由计划员确认后生成单据 |

为后续扩展预留三类基础能力：带来源 ID 的业务接口、已提交的业务事件、可追溯的单据及指标查询。AuditFlow 对接时，以 ERP 单据与审核案件的关联 ID 获取结果，重复回调按来源和事件 ID 去重。各模块可独立启用，便于未来增加新的集成能力。

## 6. 开工前要敲定的业务口径

| 待定事项 | 应准备的样本或决策 |
| --- | --- |
| 首家样板企业 | 确定主营业务、仓库与生产组织，收集采购单、销售单、收发货单、领退料单、发票和凭证样本 |
| 商品与物料 | 确定编码、计量单位换算、批次与序列号要求、退货与负库存规则 |
| 会计与成本 | 由财务确认科目、计价方式、暂估与价差、退货和冲销、关账重开、完工分摊与费用归集 |
| 权限与上线 | 确定岗位、审批额度、库房与公司范围。若用于正式账务，明确开票、银行流水、期初迁移和法定报表在 ERP 或外部系统中的责任 |

## 7. 产品验收样本

1. **采购与销售。** 采购 100 件商品，分批收货后退回 10 件，按 90 件建立应付，分两次核销。销售并发货 30 件，做部分回款。在无其他出入库的情况下，库存剩 60 件。核对可用量、销售成本和往来余额，并从报表追到来源行。
2. **制造。** 用一张 BOM 下工单，计划生产 10 件，每件标准用料 2 件。实际领料 23 件、退料 1 件，分批完工 6 件和 4 件。另有人工和制造费用时按工单归集。核对净耗 22 件、用量超标 2 件及完工成本。结算完成且所有成本已经分配时，该工单在制余额归零。
3. **更正和对账。** 对已过账且符合更正条件的单据执行一次冲销，保留原单和反向记录。重试同一过账动作，账簿只记录一次。用同一会计期间核对库存估值、应收应付明细和总账。
4. **AI 接入。** 把一笔费用送审，审核结果关联到原单。重复回传只更新同一笔关联记录。由有权限的人员完成确认，业务单据可以追到票据和审核依据。
