# 衡序 ERP 可行性分析文档

- 依据：[ERP 构建预备文档](ERP构建预备文档.md)第 3、4、6、7 节、[需求分析文档](需求分析文档.md)与[架构与技术实现文档](架构与技术实现文档.md)。
- 评估结论：首期适合进入样板数据准备和关键链路验证。企业实际账务口径、成本回收和运行容量仍需验证。本文的金额样本、工期及目标用于评审与测试。

## 3.1 分阶段验证

| 阶段 | 主要交付 | 通过条件 | 前置依赖 |
| --- | --- | --- | --- |
| A 工程与样板准备 | 空库部署、版本化迁移、环境配置、登录授权、样板账套与期初对账 | V08 通过，采购、销售、仓库和财务签认基准样本和预期结果 | 开发与验收资源，样板联系人及脱敏数据 |
| B 商贸与样板账 | 首笔采购收货与凭证贯通后扩展到采购和销售联测、库存与估值、往来核销、冲销、试算和对账 | V01–V04 及 V07、V09、V10 的商贸覆盖范围通过，实际结果可从凭证或库存追到来源行 | A、验收环境与账号 |
| C 简单装配 | BOM 版本、领退料、分批完工、工单结算与混合交付 | V05、V06 通过，工单成本、在制与账簿有签认结果 | B，样板工单与成本分摊口径 |

## 3.2 关键风险与验证

| 风险 | 影响 | 验证方式 | 预案 |
| --- | --- | --- | --- |
| 空库部署、期初分录或期初子账不一致 | 无法开账或差额滚入后续期间 | V08 检查部署、启用权限、借贷及期初控制科目 | 财务签认开账批次，启用失败时整批回滚 |
| 分批收发、退货、核销同时修改同一来源行 | 重复占用或超额核销 | V01、V02 追加并发提交及超量分配，比较各来源行余额 | 事务内锁定受影响来源，失败时返回剩余额度和冲突记录 |
| 库存和凭证提交中断，或提交后响应丢失 | 库账不一致或重复动作 | V03 在库存写入后、凭证写入前注入失败，再模拟响应丢失 | 同事务回滚，以稳定操作 ID 查询和重试 |
| 并发出库或跨仓成本竞争 | 负库存、同一业务顺序下估值不稳定 | V04 并发发货、调拨、锁超时与重试，回放流水 | 固定锁序，失败有限重试，无法执行时返回业务冲突 |
| 分批完工、成本结算与已发货同时发生 | 在制余额、成品库存价值与销售成本失真 | V05 比较工单总归集与各成本去向；追加结算重试 | 由财务签认差额规则，暂估差额缺少可靠来源时阻止结算并列明缺项 |
| 关账、冲销或补录使用错误期间 | 对账口径不一致 | V07 使用相同期间发起关账和过账，检查最终状态与反向引用 | 日期依已签认规则处理，限制跨期动作，留存更正证据 |
| 试点数据量扩大或恢复失败 | 流程延迟、对账停摆 | V09、V10 | 按查询计划与锁指标调整，独立执行备份恢复演练 |

## 3.3 首批可执行验收样本

金额均为合成样本，采用人民币。V01、V02、V05 的单价、费用和付款额只用于核对计算和追溯。试点财务另行签认科目、税额、暂估差异与正式会计处理。

| 编号 | 关联 | 固定输入与操作 | 预期结果 |
| --- | --- | --- | --- |
| V01 | S01、FR-02/06 | 采购 100 件，单价 10；收 60 和 40；从第二批退 10；价税差异为 0 的应付 900；核销 300 和 500 | 净收 90，应付发生额 900，核销 800，未结 100；来源行有 60 和 30 件的可开票分配 |
| V02 | S02、FR-03/06 | 延续 V01 商品，在无其他商品变动的样本中分批发出 20 和 10；单价 15；确认应收后到账 200 | 库存余 60、库存价值 600、销售成本 300、应收发生额 450、未结 250；发货和核销可下钻 |
| V03 | S05、FR-06 | 确认发货时模拟凭证写入前出错，然后恢复；提交后模拟客户端超时，以同 ID 重试两次，再以同 ID 改数量 | 出错时单据、流水和凭证均无部分生效；成功后只出现一组结果；同 ID 异内容被拒绝 |
| V04 | S03、FR-04 | 同仓同物料可用量 1，两笔同时各扣 1；另用两个仓库完成一笔调拨 | 仅一笔出库提交；库存与可用量无负值；调拨两侧数量互抵，公司级估值净额为 0 |
| V05 | S04、FR-05/06 | 工单 10 件，标准用料 20，领 23 退 1，材料单位成本 10；人工 40，制造费用 20；第一批完工 6 件按每件 25 暂估，其后卖出其中 2 件；第二批完工 4 件后结算。合成假设是 10 件均摊并能追溯首批去向 | 净耗 22、超用 2、总成本 280、单位实际成本 28。首批暂估 150，结算补 18，其中库存补 12、销售成本补 6。第二批按实际成本计 112。最终剩余成品价值 224、累计销售成本 56、在制余额 0 |
| V06 | S02/S04、FR-03/05/07 | 用一张订单同时销售 V05 留存的自产件与外购件；分批交付。用另一账套场景验证制造关闭 | 两类物料的预留和履约按行独立核对；可走同一销售及下钻流程；关闭制造后普通采购到销售链路可运行 |
| V07 | S05、FR-01/06/07 | 对无未处理下游的过账单执行冲销；关闭期间后提交动作；以未授权仓库账号通过界面与 API 查询及提交 | 反向记录有原动作和原因，冲销后净效应与签认样本一致；关账后动作被拒绝；未授权请求被拒且留痕 |
| V08 | S06、FR-01/06/08 | 在空 PostgreSQL 库运行迁移，创建样板账套及岗位。录入库存 10 件、单价 10、应收 50、应付 20，平衡样本配期初权益贷方 130；先尝试提交不平的期初批次，再用财务签认的平衡样本确认并重试 | 失败批次无部分写入；成功后库存控制科目与库存估值均为 100，应收科目及明细均为 50，应付科目及明细均为 20。重复提交无新增记录，普通岗位无法修改已确认期初 |
| V09 | FR-04/06/07 | 30 个活跃用户，以 10 万单据行、50 万库存流水行压测；对当前阶段已交付的 V01–V08 用例作回归 | 库存列表 P95 ≤ 1 秒、库存动作过账 P95 ≤ 2 秒；实测时长记录环境和负载 |
| V10 | FR-01/04/06 | 用备份恢复到新环境，抽查 V01 源单和凭证，装配阶段追加 V05 成本及来源核对，再完成一次新业务提交 | 账簿、库存与来源引用一致，记录恢复时间和可恢复到的时间点，新业务可正常提交 |

试点验收记录统一保存样本版本、规则版本、执行账号、操作 ID、期望值、实际值和签收人。规则变更后重跑关联业务用例和对账样本。并发、冲销、隔离和无差额对账属于发布门槛。

## 3.4 运行、安全与数据

| 监测项 | 试点门槛 | 测量与处置 |
| --- | --- | --- |
| 账实差额、重复过账、越权、负库存 | 样本一致率 100%，事件阈值 0 起 | 对账任务或库中不变量一旦检测到事件，保留操作 ID 并暂停受影响动作排查 |
| ERP 性能 | 读 P95 ≤ 1 秒，过账 P95 ≤ 2 秒 | 按需求 1.4 同负载测量；达到告警门槛时查看慢查询与锁等待 |
| 业务时间可用性 | 月度 ≥ 99.5% | 按分钟探测，记录失败段及恢复时间 |
| 恢复目标 | 暂定 RPO ≤ 24 小时、RTO ≤ 4 小时 | 每轮验收环境恢复演练用实际备份与附件执行，记录测量值 |

消息日志保存关联 ID、耗时和错误码。按角色授权查看凭证及敏感业务数据，试点只使用合成或必要的脱敏数据。日志保存期限、备份保留周期和账套资料访问范围由样板企业确认。正式上线前还需确认适用的财务、税务、个人信息与数据处理要求，以及实际采用的依赖许可证。

## 3.5 工期和投入估算

工作量按工程人日估算，包含设计、实现、测试与修复。按工程从零建设估算。假设团队熟悉初选技术栈，有业务人员提供样本，两位工程人员可分担部分工作。以每周合计 10 人日计算，纯工程容量约 6–9 周，实际日历工期还取决于各阶段依赖和可并行程度。等待样本和业务签认的时间另计。区间用于范围讨论，团队可用性和工期目标尚待确认。

| 工作包 | 人日估算 | 主要时间驱动 |
| --- | --- | --- |
| 工程基础与样板数据 | 12–18 | 运行环境、迁移、身份权限、过账规则与样板期初 |
| 采购、销售、库存和样板账 | 26–38 | 单据状态、估值、核销、冲销、对账及并发 |
| 简单装配和工单差额 | 10–16 | BOM、分批完工、已发货差额和在制核对 |
| 压测、恢复及试点修复 | 6–10 | 回归、数据规模和权限 |
| 合计 | 54–82 | 范围和规则签认后重估 |

实施预算用 `Σ(角色人日 × 对应日成本) + 环境一次性费用` 估算；持续费用用计算、数据库与备份的月用量及实际单价。需求分析 1.1 的 30,000 元与每月 500 元为 ROI 演算输入，正式估算以实际日成本及服务报价替换。缺乏样板批量、计时基线和运行报价时，经济可行性待定。
